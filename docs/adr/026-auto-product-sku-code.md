# ADR-026: 상품 코드와 SKU 코드는 서버가 자동 발급하고, 입력을 받지 않는다

- 상태: Accepted
- 날짜: 2026-10-13

## 컨텍스트
상품 코드는 등록 요청에서 사람이 직접 입력했고, SKU 코드는 선택 입력(생략하면 자동 생성)이었다. 브랜드(ADR-023)·카테고리(ADR-025)·창고·지점(ADR-021) 코드는 이미 서버 규칙으로 통일됐는데 상품·SKU 코드만 형식이 제각각이었다. SKU 코드가 `상품코드-옵션코드…`로 만들어지므로 상품 코드가 자유 입력이면 SKU 코드의 형식도 정해지지 않는다.

## 결정
- **상품 코드 형식**: `{브랜드코드}-{카테고리코드}-{일련번호 4자리}`. 예: `YNX-RKT-0001`. 일련번호는 9999를 넘으면 자릿수가 늘어난다.
- **자동 발급**: 상품 등록 요청은 `productCode`를 받지 않고(보내도 무시) 응답으로만 준다.
- **채번**: 브랜드+카테고리 조합별로 마지막 발급 번호를 `product_code_sequence`에 저장하고, 그 행을 비관적 락으로 잠가 올린다. 번호는 한 번 쓰면 다시 쓰지 않는다. 조합의 첫 행을 만드는 순간의 경합은 같은 브랜드의 발급을 브랜드 행 잠금으로 직렬화해 막는다. 과거에 직접 입력된 코드와 겹치면 다음 번호로 넘어간다.
- **브랜드 코드가 없는 기존 브랜드**는 상품 등록을 409 `BRAND_CODE_REQUIRED`로 거절한다. 브랜드 코드를 먼저 지정한다(ADR-023).
- **재발급**: 상품의 브랜드 또는 카테고리를 바꾸면 새 조합의 다음 번호로 코드를 다시 발급해 수정 응답에 담는다. 같은 값을 다시 보내거나 다른 필드만 수정하면 코드를 유지한다.
- **SKU가 있는 상품의 브랜드 변경은 막는다**(409 `PRODUCT_BRAND_LOCKED`). SKU 코드는 상품 코드에서 만들어져 바코드 라벨·작업 지시에 쓰이므로 다시 발급하지 않는다. 카테고리는 ADR-025에서 이미 스펙·SKU가 있으면 바꿀 수 없다.
- **SKU 코드·이름 자동 전용**: SKU 등록 요청은 `skuCode`, `skuName`을 받지 않고(보내도 무시) 항상 `상품코드-옵션코드…`, `상품명 (옵션값/옵션값)`으로 만든다. 옵션 값에 코드가 없거나 결과가 50자(코드)·200자(이름)를 넘으면 400이다. 이름의 사후 수정(`PATCH`)은 유지하고, 코드는 수정할 수 없다.
- **기존 데이터**: 이미 만든 상품·SKU 코드는 변환하지 않는다.

## 근거
- 코드는 표시용 이름표이고 모든 참조는 `Long xxxId`이므로, 브랜드·카테고리 변경에 따른 상품 코드 재발급이 재고·입고·출고 데이터에 영향을 주지 않는다.
- 코드에 브랜드와 종류가 드러나 현장에서 코드만 보고 구분할 수 있다. SKU 코드까지 `YNX-RKT-0001-2U-G5-BLK`처럼 이어져 25자 안팎이라 50자 제한에 여유가 있다.
- SKU 코드는 라벨에 인쇄되어 바뀌면 현장 혼선이 생기므로, SKU가 있는 상품은 코드가 바뀌는 변경 자체를 막는 쪽이 재발급보다 안전하다.
- 코드를 입력으로 받지 않으면 중복·표기 오류를 사람이 처리하지 않아도 된다.

## 검토했던 대안
- 상품 코드 직접 입력 + 형식 검증: 기각. 번호 충돌과 오타를 사람이 계속 처리해야 한다.
- 전역 단일 일련번호(`YNX-RKT-0007`): 기각. 조합 안에서 1부터 읽히지 않아 의미가 약하다. 단일 채번 행의 경합 이점은 브랜드 행 잠금으로 얻는다.
- 상품 코드를 한 번 발급하면 고정(브랜드·카테고리 변경 시에도 유지): 기각. 코드가 실제 브랜드·카테고리와 어긋나 거짓 정보가 된다(ADR-021과 같은 이유).
- SKU 이름은 직접 입력 허용: 기각. 상품명·옵션값으로 만들어 일관되게 하고, 필요하면 사후 수정으로 바꾼다.

## 영향
- 마이그레이션 `V25__create_product_code_sequence.sql`.
- 코드: `ProductCodeIssuer`, `ProductCodeSequenceRepository`(+어댑터·엔티티), `BrandRepository.findByIdForUpdate`, 상품 등록·수정 서비스, SKU 등록 서비스, 요청 DTO.
- 에러 코드: `BRAND_CODE_REQUIRED`, `PRODUCT_BRAND_LOCKED` 추가. 상품 등록의 `DUPLICATE_PRODUCT_CODE`는 더 이상 나오지 않는다.
- 명세: `api/product.md`. 프론트: 상품·SKU 등록 화면에서 코드·SKU 이름 입력란을 없애고, 응답의 코드를 표시한다. 브랜드를 바꾼 수정 응답의 `productCode`가 바뀔 수 있다.
