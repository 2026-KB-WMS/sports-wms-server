# ADR-019: 재고 할당은 부분 할당을 허용하고, SKU를 골라 할당할 수 있게 한다

- 상태: Accepted
- 날짜: 2026-10-12

## 컨텍스트
`POST /allocations`는 발주 전체를 all-or-nothing으로 할당했다. 한 항목이라도 가용 재고가 모자라면 아무것도 할당하지 않고 409 `INSUFFICIENT_STOCK`이었다. 그래서 재고가 일부만 있어도 먼저 내보낼 수 없었고, 여러 SKU 중 일부만 따로 할당할 수도 없었다. 명세 "확정 필요"에 "재고 부족 시 부분 할당 허용 여부(현재 전체 실패)"가 미결로 남아 있었다.

## 결정
- **부분 할당 허용**: 항목별로 가용 재고만큼 FEFO로 할당한다. 한 항목이 0이어도 다른 항목은 할당한다.
- **전량 부족은 거절**: 대상 항목 전부에서 하나도 할당하지 못하면 아무것도 만들지 않고 409 `INSUFFICIENT_STOCK`이다(빈 목록으로 201을 내지 않는다).
- **부족분은 응답으로 알린다**: 성공 응답에 `shortages[]`(`skuId`, `requestedQuantity`, `allocatedQuantity`, `shortageQuantity`)를 추가한다. 부족이 없으면 빈 배열이다. `requestedQuantity`는 이번 호출에서 할당하려던 잔여 수량이다. 기존 응답 필드는 그대로다.
- **SKU 선택 할당**: 요청 body에 선택 필드 `skuIds`를 추가한다. 생략하면 발주 전체(기존 동작), 주면 그 SKU 항목만 대상이다.
  - 한 발주 안에서 SKU는 중복될 수 없으므로(`uk_store_order_line_order_sku`) SKU로 항목이 정해진다.
  - 발주에 없는 SKU, 빈 배열, null 원소는 400 `VALIDATION_ERROR`다. 빈 배열을 "전체"로 해석하지 않는다.
  - 중복 ID는 한 번만 처리한다. 선택한 SKU가 모두 이미 할당 끝났으면 409 `ALREADY_ALLOCATED`, 일부만 끝났으면 남은 것만 처리한다.
- **나머지 할당**: 재고가 들어온 뒤 같은 요청을 다시 보내면 잔여 수량(`요청 - 할당 - 출고`)만큼 이어서 할당된다. 별도 처리는 필요 없다.
- 출고 생성은 바뀌지 않는다. 그 시점에 출고에 묶이지 않은 `ALLOCATED` 할당을 전부 한 출고로 묶는다.

## 근거
- 재고가 일부만 있어도 먼저 출고할 수 있어야 현장이 막히지 않는다. 잔여 수량 계산과 한 발주 다중 출고는 이미 구현돼 있어서, 막고 있던 것은 할당 단계의 부족 검사뿐이었다.
- 전량 부족을 성공으로 돌려주면 호출자가 실패를 응답 본문으로만 알 수 있다. 아무것도 못 잡았을 때는 기존처럼 409로 구분한다.
- 일부만 잡힌 사실은 응답에 구조화해 알려야 프론트가 "일부만 할당됨"을 표시할 수 있다. 에러 메시지에 문자열로 담던 방식은 성공 응답에는 쓸 수 없다.
- 빈 `skuIds`를 전체로 해석하면 클라이언트의 필터 버그가 발주 전체 할당으로 이어진다. 거절이 안전하다.

## 검토했던 대안
- 수량을 직접 지정해 할당(`quantity` 입력) — 이번에는 제외. 필요해지면 `skuIds`를 항목별 수량 입력으로 확장할 수 있다.
- 부족한 항목이 있으면 전체 실패를 유지하되 `allowPartial` 플래그로 선택 — 기각. 플래그를 빼먹은 호출이 계속 막히고, 부분 할당이 기본이어야 하는 현장 요구와 맞지 않는다.
- 항목 식별자로 `storeOrderLineId` 사용 — 기각. SKU가 발주 안에서 유일하고 프론트가 SKU 기준으로 다루기 쉽다.
- 전량 부족도 201과 빈 `items`로 응답 — 기각. 아무것도 할당되지 않았다는 사실이 상태 코드에서 드러나지 않는다.

## 영향
- **클라이언트**: 할당 응답의 `shortages`가 비어 있지 않으면 "일부만 할당됨"으로 보여 줘야 한다. 한 번 호출로 발주 전체가 할당됐다고 가정하면 안 된다.
- **재배정·취소**: 할당이 남아 있으면 재배정이 막히는 가드(409 `ORDER_IN_FULFILLMENT`)와 승인 이후 취소가 할당을 해제하는 동작은 그대로다.
- **부분 종결**: 부족분을 더 보내지 않을 때는 기존 `complete-partial`로 종결한다.
- 코드: `StockAllocationService`(대상 선택, FEFO 부분 배치), `StockAllocateRequest`·`StockAllocateCommand`·`StockAllocateResult`·`StockAllocateResponse`. DB 마이그레이션은 없다.
- 문서 갱신: `api/outbound.md`, `domain/outbound.md`, `api/store-order.md`, `scenario/e2e.md`.
