# ADR-003 마스터 데이터 관리 주체를 본사 관리자로 일원화

## 상태
`Accepted` (2026-09-21)

## 컨텍스트
초기 API 명세를 작성하면서 일부 엔드포인트(예: 공급처 관리, 창고구역 수정)의 담당 역할이 창고 관리자로 지정되어 있었다. 그러나 상품·창고·지점처럼 이미 본사가 관리하기로 한 마스터 데이터와 일관성이 없었다.

## 결정
거래처·마스터 성격의 모든 엔티티는 본사 관리자(`HQ_ADMIN`)만 등록·수정·비활성화할 수 있다.
- 대상: Brand/Category/Product/ProductSKU/OptionGroup/OptionValue, Warehouse/WarehouseSection, Store, Supplier, WarehouseMember/StoreMember(관리자 배정)
- 창고·지점은 자신의 소속 범위 내에서 조회만 가능하며, 발주 등록 등 현장 운영에 필요한 참조 용도로만 마스터를 사용한다.

## 근거
- 마스터 데이터가 여러 주체에 의해 산발적으로 수정되면 데이터 정합성이 깨지기 쉽다.
- 조직 구조상 상품·거래처·조직 정보에 대한 책임은 본사에 있고, 창고·지점은 실행 조직이다.
- 전 도메인에 동일한 권한 규칙을 적용하면 API 인가 로직(역할 기반)이 단순해진다.

## 검토했던 대안
- 창고가 담당 공급처·구역 정보를 직접 관리 — 기각. 여러 창고가 같은 공급처를 공유하는 경우 데이터가 중복·불일치할 위험이 있다.

## 영향
- API 명세: 공급처 5개 엔드포인트, `PATCH /warehouses/sections/{id}` 담당을 본사로 수정.
- 기능 명세: HQ-09(공급처 관리) 항목 신규 추가.
- 업무 상태 전이도: "마스터 데이터 관리 주체" 표 신규 작성.
