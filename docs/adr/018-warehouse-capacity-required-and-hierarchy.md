# ADR-018: 창고·구역 수용량을 필수로 하고, 상하위 수용량 관계를 검증한다

- 상태: Accepted
- 날짜: 2026-10-10

## 컨텍스트
창고 `totalCapacity`와 구역 `capacity`는 선택 입력(기본 0)이었고, "하위 구역 수용량 합 ≤ 상위 구역 ≤ 창고 `totalCapacity`" 관계는 어디서도 검증하지 않았다(명세 미결, [보류] #10). 용량을 비워 두면 한도가 없는 것과 같아져, 입고 적치 때의 구역 수용량 검사(`SECTION_CAPACITY_EXCEEDED`)만 남고 상하위 수용량은 서로 아무 관계가 없었다.

## 결정
- **수용량 필수**: `POST /warehouses`의 `totalCapacity`, `POST /warehouses/sections`의 `capacity`는 필수다(없으면 400 `VALIDATION_ERROR`). 값은 0 이상이며 0도 허용한다. 구역은 상위·하위 구분 없이 모두 필수다. 수정 API(`PATCH`)는 기존대로 값이 있는 필드만 바꾼다.
- **관계 검증**:
  - 같은 상위 구역 아래 **활성** 직속 하위 구역들의 `capacity` 합 ≤ 상위 구역 `capacity`
  - 창고의 최상위 **활성** 구역들의 `capacity` 합 ≤ 창고 `totalCapacity`
  - 한 단계만 비교한다(손자 구역은 직속 부모와만 비교). 비활성 구역은 합계에서 뺀다.
- **0은 한도 0**: "미설정"으로 보지 않는다. 상위 수용량이 0이면 0보다 큰 하위 구역은 등록할 수 없다.
- **검증 시점과 오류**:
  - 구역 등록, 구역 `capacity` 증가, 구역 재활성화에서 합계가 상위 한도를 넘으면 409 `PARENT_CAPACITY_EXCEEDED`.
  - 구역 `capacity` 또는 창고 `totalCapacity`를 활성 하위 구역 합보다 작게 바꾸면 409 `CAPACITY_BELOW_CHILDREN`. (기존 `CAPACITY_BELOW_USAGE`는 현재 사용량 기준이며 그대로 둔다.)
  - 수용량을 줄이는 변경과 비활성화는 상위 한도 검증을 하지 않는다(한도를 더 쓰지 않는다).
- **동시성**: 합계를 비교하는 변경은 창고 행을 `SELECT ... FOR UPDATE`로 잠근 뒤 확인한다. 구역 수정·재활성화는 구역 행 → 창고 행 순으로 잠그고, 창고 수정은 창고 행만 잠근다.
- **기존 데이터**: 마이그레이션으로 바꾸지 않는다. 컬럼은 이미 `NOT NULL DEFAULT 0`이고, 한도가 0인 기존 창고·구역은 수용량을 먼저 채워야 하위 구역을 추가·재활성화할 수 있다. 이미 합이 상위를 넘는 데이터는 새로 늘리거나 재활성화하려는 순간에만 막히고, 읽기·재고 처리·이름 변경 등은 영향받지 않는다.

## 근거
- 수용량이 선택이면 검증이 켜지는 조건("0은 미설정")을 따로 정의해야 하고, 그러면 같은 창고 안에 한도가 있는 구역과 없는 구역이 섞여 규칙이 불분명해진다. 필수로 하면 규칙이 하나로 정리된다.
- 입고 적치 검사는 구역 단위라, 상위 한도를 넘는 구역을 잡지 못한다. 등록·수정 시점에 막아야 적치 가능 용량이 실제 공간을 넘지 않는다.
- 비활성 구역은 적치할 수 없으므로 한도를 차지하지 않는다. 재활성화 때 다시 확인한다.

## 검토했던 대안
- 상위 수용량 0을 "미설정"으로 보고 검증 생략 — 기각(결정). 같은 창고에 한도 있는 구역과 없는 구역이 섞여 규칙이 모호해진다.
- 수용량 필수는 최상위 구역·창고만 요구 — 기각. 말단 구역은 적치 한도의 실제 단위라 비어 있으면 안 된다.
- 마이그레이션으로 기존 0 수용량을 하위 합으로 채움 — 기각. 임의 값을 만들어 넣게 된다.
- 하위 전체(손자 포함) 합을 최상위와 비교 — 기각. 직속 비교를 단계마다 지키면 전체가 보장된다.

## 영향
- **기존 창고·구역**: 수용량이 0인 곳은 하위 구역을 새로 등록하거나 비활성 구역을 재활성화하기 전에 `PATCH`로 수용량을 채워야 한다.
- **클라이언트**: 창고·구역 등록 폼은 수용량을 필수 입력으로 바꾸고, 409 `PARENT_CAPACITY_EXCEEDED`·`CAPACITY_BELOW_CHILDREN` 안내가 필요하다.
- `WarehouseRepository.findByIdForUpdate`, `WarehouseSectionRepository.sumActiveCapacity`가 추가된다. 문서 갱신: `api/warehouse.md`.
