# ADR-024: SKU 수량 단위는 서버 허용 목록(EA, BOX, SET)으로 제한한다

- 상태: Accepted
- 날짜: 2026-10-13

## 컨텍스트
SKU의 수량 단위(`unit`)가 자유 입력(20자 이하)이라 `EA`, `ea`, `개`, `박스`처럼 같은 단위가 제각각 저장될 수 있다. 단위는 재고·입출고 수량을 해석하는 값이라 표기가 갈리면 이후 정리가 어렵다.

## 결정
- **허용 목록**: `EA`(개), `BOX`(박스), `SET`(세트). 기본값은 지금처럼 `EA`다.
- **검증**: SKU 등록의 `unit`이 목록 밖이면 400 `VALIDATION_ERROR`다. 빈 문자열도 거절하고, 대소문자·공백은 정확히 일치해야 한다(`ea`, ` EA`는 거절).
- **목록 조회**: `GET /products/skus/units`가 `code`, `name` 목록을 돌려주며 로그인한 모든 역할이 읽을 수 있다. 프론트 드롭다운은 이 목록으로 채운다. 창고·지점의 `management-types`와 같은 고정 코드 목록 방식이다.
- **기존 데이터**: 이미 저장된 SKU의 `unit`은 변환하지 않는다. `unit`은 SKU 수정 API 대상이 아니므로 목록 밖 값은 그대로 남는다.
- **저장 형태**: 컬럼은 `VARCHAR(20)`을 유지한다. enum으로 바꾸지 않아 목록 밖 기존 값을 읽을 수 있고, 허용 값을 늘릴 때 마이그레이션이 필요 없다.

## 근거
- 서버가 값을 강제해야 프론트 외의 호출(스크립트, 다른 클라이언트)도 같은 표기를 쓴다.
- 허용 목록 API를 두면 프론트가 값을 하드코딩하지 않아 목록 변경이 한 곳에서 끝난다.
- 기존 값을 일괄 변환할 기준이 없으므로(`개`를 `EA`로 볼지 등) 변환하지 않고 신규 등록부터 적용한다.

## 검토했던 대안
- 프론트 드롭다운만 두기: 기각. 서버에 직접 호출하면 자유 값이 여전히 들어간다.
- 입력을 대문자로 정규화해 `ea`도 받기: 기각. 목록 API의 `code`를 그대로 보내면 되므로 정규화 규칙을 늘리지 않는다.
- DB enum 컬럼으로 변경: 기각. 기존 목록 밖 값을 읽지 못하고 값 추가마다 마이그레이션이 필요하다.
- 단위 마스터 테이블(관리자가 추가): 기각. 단위가 세 가지뿐이고 추가·삭제 요구가 없다.

## 영향
- 코드: `SkuUnit` enum, `ProductSkuService.registerSku`의 단위 검증, `ProductCodeController`·`ProductCodeUseCase`·`ProductCodeService`.
- 명세: `api/product.md`. 프론트: SKU 등록 화면의 단위 입력을 `GET /products/skus/units` 목록 드롭다운으로 바꾼다.
- 목록 밖 단위(`PACK` 등)가 필요해지면 `SkuUnit`에 값을 추가한다.
