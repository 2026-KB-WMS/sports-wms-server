# ADR-002 PurchaseOrder 확정(CONFIRMED) 권한을 본사 관리자로 지정

## 상태
`Accepted` (2026-09-21)

## 컨텍스트
창고가 공급업체에 발주하는 흐름에서, 처음에는 창고 관리자가 발주 등록부터 확정까지 전부 처리하는 것으로 가정했다. 그러나 실제 공급처 발주 확정(가격·수량·거래 조건이 실제로 발생하는 시점)은 재무·거래 책임이 따르는 행위이므로 창고 관리자 단독 권한으로 두기 어렵다는 문제가 제기됐다.

## 결정
`PurchaseOrder` 상태 전이 권한을 요청과 확정으로 분리한다.
- `REQUESTED` (등록): 창고 관리자 — 재고 보충 필요성에 따라 요청만 한다.
- `REQUESTED → CONFIRMED` (확정): 본사 관리자 — 공급처·품목·수량을 검토해 실제 발주를 확정한다.
- `REQUESTED → CANCELED`: 창고 관리자(작성자, 확정 전에 한함)
- `CONFIRMED → CANCELED`: 본사 관리자(확정 권한자가 취소도 담당)

## 근거
- 마스터 데이터(공급처·상품)와 마찬가지로 대외 거래가 발생하는 확정 단계는 본사가 통제해야 통일된 거버넌스가 유지된다.
- 창고는 현장 운영(재고 보충 필요성 판단, 입고 검수)에 집중하고, 대외 계약·재무 책임은 본사가 지는 구조가 기존 조직 구조와 일치한다.

## 검토했던 대안
- 창고 관리자가 요청부터 확정까지 전담 — 기각. 현장 인력이 공급처 발주 조건까지 결정하면 본사의 구매 통제가 어려워진다.

## 영향
- API 명세: `PATCH /purchase-orders/{id}/confirm`, `PATCH /purchase-orders/{id}/cancel` 담당(`담당` 필드) 본사 관리자로 수정.
- 업무 상태 전이도의 PurchaseOrder 상태 전이표에 역할 재정의 반영.
