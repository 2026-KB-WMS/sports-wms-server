# 도메인 이슈 생성

`gh` CLI로 이슈를 생성한다. 이슈 생성은 외부에 남는 작업이므로 **제목/본문 초안을 먼저 보여주고 승인받은 뒤** 생성한다.

## 구조
- 부모 1개: `[<Domain>] <도메인명> 도메인 구현` (예: `[Product] 상품 도메인 구현`)
- 서브이슈 5개 (GitHub 네이티브 서브이슈로 연결):
  1. 도메인 모델 + 마이그레이션
  2. 포트 + 저장소 어댑터
  3. 서비스 로직
  4. 웹 어댑터 + 응답 포맷
  5. 테스트
- 기존 라벨/마일스톤만 사용한다(새 라벨 만들지 않음). 마일스톤은 도메인명과 일치하는 것을 선택. `.github/ISSUE_TEMPLATE/`의 feature 템플릿 형식을 따른다.

## 부모 이슈 본문
- Notion 명세 링크 (ERD / 기능 명세 / API 명세)
- **구현 범위**: 포함되는 엔티티, API 엔드포인트 수와 목록 요약
- **서브이슈 진행 체크리스트**: `- [ ] #번호 제목` 형태
- 알려진 제약/보류 사항(있다면)

## 서브이슈 본문
- 해당 레이어에서 만들 클래스/파일 목록
- 완료 조건(체크박스)
- 부모 이슈 참조

## 순서
1. 도메인의 ERD/API 명세를 읽고 구현 범위를 파악한다.
2. 초안 제시 → 승인 → 부모 생성 → 서브이슈 5개 생성 및 부모에 연결 → 부모 본문 체크리스트에 실제 번호 반영.
3. Notion "WMS 개발 일정" DB에 도메인 페이지가 없으면 만들 것인지 사용자에게 제안한다.
4. 생성된 이슈 번호를 사용자에게 알린다.
