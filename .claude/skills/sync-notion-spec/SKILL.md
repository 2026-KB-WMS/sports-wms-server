# 명세 ↔ 코드 대조

1. 대상 도메인을 확인한다.
2. `docs/README.md` 표에서 명세 위치를 확인한다. 레포에 있으면 `docs/`(`api/`, `domain/`, `adr/`)를, 아직 Notion에 있으면 Notion의 API 명세 상세 페이지, ERD 데이터 사전, 업무 상태 전이도를 읽는다.
3. 코드에서 다음 항목을 비교한다.
   - 엔드포인트: HTTP 메서드, 경로, 요청/응답 필드명(camelCase), 필수 여부, 검증 규칙
   - 응답: `data.items` 형태, 상태 코드, `errorCode` 값(도메인 전용 코드)
   - 데이터: 컬럼명/타입/기본값(예: 수량 BIGINT), 상태 enum 값, Flyway 마이그레이션
   - 비즈니스 규칙: 상태 전이, 경계 조건(예: 안전재고 "미만")
   - ADR 준수: `docs/adr/`의 결정과 어긋나는 구현이 없는지
4. 결과를 표로 정리한다: `항목 | 명세 | 코드 | 심각도`.
5. **임의로 수정하지 않는다.** 어느 쪽을 맞출지는 사용자가 결정한다. 결정되면 코드 수정은 단일 이슈(예: "명세-코드 불일치 수정")로 묶어 처리하고, 명세 변경은 명세가 있는 곳(레포 `docs/` 또는 Notion)에 반영한다.
6. 보류 항목은 Notion "[보류]" 페이지에 기록한다.

단순 대조만 필요하면 `spec-reviewer` subagent에 위임해 요약 결과만 받는다.
